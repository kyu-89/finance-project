# 우리집 재무 디자인 시스템

이 문서는 화면마다 스타일을 새로 만드는 대신, 앱 전체에서 반드시 재사용할 기준을 정합니다. 기준 구현체는 `src/app/design-system.css`와 `src/components/FormField.tsx`입니다.

## 레이아웃

| 환경 | 콘텐츠 폭 | 가로 여백 | 세로 여백 |
| --- | --- | --- | --- |
| 웹 | 앱 메인 영역 전체 | 20~28px | 28px |
| 웹(≥1280px) | 최대 1920px(LNB 포함), 초과분은 좌우 여백 | 20~40px | 28px |
| 모바일 | 화면 전체 | 16px | 24px |

- `tds-page`만 페이지의 외곽 여백을 담당합니다. 개별 화면에서 음수 margin으로 외곽 정렬을 맞추지 않습니다.
- 웹은 LNB를 제외한 남은 공간을 모두 사용합니다. 데이터 화면은 별도 최대폭을 두지 않으며, 입력 폼처럼 읽기 폭이 중요한 영역만 내부 grid를 제한합니다.
- 모바일은 데스크톱 표를 축소하지 않습니다. 정보가 많은 표는 카드형 행 또는 가로 스크롤 중 내용 이해가 쉬운 방식을 선택합니다.

## 타이포그래피

| 토큰 | 크기 | Weight | 용도 |
| --- | --- | --- | --- |
| `--text-display` | clamp(28px, 2.4vw, 36px) | 700 | 홈 대시보드 카드의 대표 숫자(자산 총액 등) |
| `--text-title-1` | clamp(25px, 2vw, 30px) | 700~750 | 페이지 타이틀(`tds-title`), 핵심 KPI 숫자 |
| `--text-title-2` | 20px | 700~800 | 섹션 소제목(`h2`), 카드 강조 숫자 |
| `--text-title-3` | 16px | 800 | 보조 타이틀/모듈 헤딩 |
| `--text-body-1` | 15px | 400 | 기본 본문 텍스트 |
| `--text-body-2` | 14px | 400~750 | 보조 설명, 버튼·링크·legend 텍스트 |
| `--text-caption` | 13px | 650 | 폼 라벨, eyebrow, 캡션 |
| `--text-micro` | 11px | 400~800 | 배지, 차트 라벨, 보조 소형 텍스트 |

## 간격과 모서리

- 간격은 `4 / 8 / 12 / 16 / 20 / 24px` 단위만 사용합니다.
- 간격 스케일은 4/8/12/16/20/24px에 더해 와이드 화면 섹션 간격용 32/40/48px을 포함한다.
- 입력·버튼은 12px, 표면·카드는 18px radius를 사용합니다. 모바일 표면은 16px입니다.
- 같은 계층의 카드·행·드로어 안쪽 여백은 20px(모바일 16~20px)으로 맞춥니다.

## 버튼과 상태

- `tds-primary-button`: 한 영역의 대표 행동. 파란 채움, 44px(모바일 48px) 높이.
- `secondary-button`, `tds-button-secondary`: 보조 행동. 흰 배경과 테두리, 동일한 높이.
- 파괴 행동은 secondary 규격을 유지하고 위험 색상 텍스트만 사용합니다. 위치나 크기로 다른 버튼을 밀어내지 않습니다.
- `tds-chip`: 정보 배지는 30px, 누를 수 있는 필터·선택 칩은 버튼으로 44px 이상입니다.
- `tds-button-ghost`는 툴바 안 3차 행동에, `tds-text-link`는 인라인 텍스트 링크("더보기" 등)에 사용한다.
- `tds-badge`는 비대화형 상태 표시(수입/지출/완료/예정 등)에, `tds-chip`은 클릭 가능한 필터·선택에만 사용한다.
- 탭·필터칩·월 선택기 등 모든 선택 상태는 브랜드 블루(blue-50 배경/blue-600 텍스트) 하나로 통일한다.
- 상태 변경 select는 128px(모바일 116px) 폭으로 통일합니다.

## 입력과 검증

- 텍스트·날짜·금액·선택 입력은 44px(모바일 48px), 12px 좌우 padding, 14px(모바일 16px) 본문 글자를 사용합니다.
- 날짜 입력은 반드시 보이는 라벨을 둡니다. placeholder만으로 필드 의미를 전달하지 않습니다.
- 폼 필드는 `FormField`를 사용합니다. native `required` 속성 또는 `FormField`의 `required` prop으로 라벨 우측에 빨간 `필수`가 표시됩니다. 버튼·칩처럼 입력 요소가 아닌 선택 UI는 후자를 사용합니다.
- 선택 입력은 별도 빨간 표기를 하지 않습니다. 복잡한 값은 `hint`로 설명합니다.
- 오류는 해당 필드 가까이에, 저장 성공·실패는 토스트 정책에 따라 표시합니다.

## 오버레이와 피드백

- 생성·수정은 `AddDrawer`를 사용합니다. 웹에서는 우측 640px, 모바일에서는 하단 시트(최대 88dvh)입니다.
- 토스트는 화면 기준 고정 위치이며, 모바일에서는 하단 LNB 위에 표시됩니다. 콘텐츠 레이아웃을 밀지 않습니다.
- 클릭·hover는 색상과 그림자만 전환합니다. 버튼의 위치·폭·주변 레이아웃은 변하지 않습니다.

## 접근성과 반응형

- 모든 상호작용 요소는 키보드 포커스 링을 유지합니다.
- 모바일의 주요 조작 요소는 48px 높이와 8px 이상의 인접 간격을 지킵니다. 표 안의 상태 변경·월 선택처럼 행 밀도를 유지해야 하는 보조 조작만 40px을 예외로 합니다.
- `prefers-reduced-motion`을 존중합니다.
- 한 줄 UI는 금액·상태·짧은 라벨에만 사용합니다. 설명·오류·긴 사용자 데이터에는 적절한 줄바꿈 또는 펼침을 제공합니다.
