# 대시보드 구성원 필터·드릴다운 구현 계획

**목표:** PRD §3.1, §8.4, §20.1의 `가구 → 구성원 → 대분류 → 거래` 흐름을 기존 대시보드 기간 필터와 결합한다.

## 범위

- 구성원 목록과 `미지정`을 대시보드 전역 필터로 제공한다.
- 거래의 구성원 귀속은 `beneficiary_member_id`(비용대상)를 우선하고, 없으면 `payer_member_id`(거래자)를 사용한다.
- 구성원 필터를 KPI, 추이, 카테고리, 결제수단, YoY, 원인 거래에 동일하게 적용한다.
- 구성원별 소비 차트에서 구성원을 선택하면 해당 구성원의 대분류 구성으로 내려가고, 대분류를 선택하면 원인 거래까지 내려간다.
- 구성원 필터에서는 가구 공용 예산을 개인 예산으로 오인하지 않도록 예산 KPI 계산에서 제외하고, 예산 대 실제 차트에는 가구 예산 참고값임을 표시한다.
- 현재 자산 KPI/자산 구성은 상품의 `owner_member_id`로 필터링한다. 월별 스냅샷은 구성원 차원을 저장하지 않으므로 과거 비교·추이는 가구 전체임을 명시한다.

## 구현 순서

1. `dashboard-calculations.ts`에 구성원 귀속·필터·소비 집계 순수 함수를 추가하고 단위 테스트를 먼저 작성한다.
2. `snapshots.ts`의 현재 순자산 계산에 선택적 구성원 필터를 추가한다.
3. 대시보드의 URL 파라미터, 데이터 계산, 필터 칩, 구성원별 소비, 드릴다운 상세를 연결한다.
4. unit test, lint, build를 실행하고 HANDOFF를 갱신한다.

## 비범위

- 과거 월별 구성원 자산 스냅샷 스키마 변경
- 구성원 CRUD UI
- 공동명의 복수 구성원 연결 모델
