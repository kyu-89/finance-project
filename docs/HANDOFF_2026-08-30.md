운영 기준 원본: `2026년 (1).xlsm`

## 1. 현재 상태

- Excel 파일을 시스템의 진실의 원천으로 보고 월별 거래 import 로직을 보완했다.
- 월별 시트의 좌측 수입표와 우측 지출표를 분리해서 파싱한다.
- 요약행, 템플릿행, 0원 행, 문자형 주석행은 거래로 만들지 않는다.
- 실제 거래의 대분류·소분류를 분리해 저장한다.
- 수입 카테고리도 import 대상에 포함한다.
- 빈 문자열 UUID를 `null`로 정규화해 Supabase UUID 오류를 방지했다.

## 2. Excel import 검증 결과

대상 workbook 감사 테스트 결과:

- 월별 시트 거래 파싱 오류: 0건
- 수입 대분류/소분류 매핑 테스트 통과
- 지출 대분류/소분류 매핑 테스트 통과
- 기존 구조화 시트 파서 테스트 통과

주의: 날짜가 비어 있는 행은 원본에서 월별 예정/템플릿 행으로 사용되므로 임의 날짜를 만들어 거래로 저장하지 않는다.

## 3. 중복 거래 처리 결과

import 중복 판정 키:

`거래일자 + 거래유형 + 금액 + 내용 + 결제수단`

import 결과의 “중복 600여 건”은 운영 DB에 이미 같은 거래가 존재해 재삽입을 건너뛴 원본 행 수다. 운영 DB 자체에서 동일 키로 반복 저장된 활성 거래를 별도로 검사한 결과는 5건이었다.

- 중복 그룹별 최초 저장 1건 유지
- 나머지 5건 soft-delete 처리
- 실제 DELETE가 아니므로 삭제함에서 30일 내 복구 가능
